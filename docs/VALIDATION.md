# 当前验收

当前产品版本：**1.5.7** · 2026-11-04。正式交付身份以 GitHub Release 对应标签和包内 release.json 为准。

## 产品修复

1.5.7 修复发布验收发现的 GitHub 附件中文名被剥除问题：构建前缀集中配置为 ASCII，公开前回读名称、哈希和下载 URL。1.5.6 的不可变附件保留并补充已知问题说明；不能把该版已成功构建等同于包管理清单链接可用。以下客户端退出与恢复记录属于 1.5.6 的功能验证，1.5.7 不改变这些操作逻辑。

Kumiryo 原失败操作发生在退出阶段，尚未写入；原 DPAPI 备份可解密，配置与初始原件一致。工作进程已是管理员，旧摘要“可能以管理员运行”会误导排查。同一退出时段记录到 Flutter 异常，不能仅凭时间关系确定单条线程消息是全部异常的唯一原因。

1.5.6 移除外部 WM_QUIT，增加预览授权的精确界面退出兜底，并区分初始原件与写入恢复备份。**136 项功能检查通过**。两轮 Windows Sandbox 实测通过：普通权限 10 项、管理员 11 项，覆盖拒绝未授权退出、授权后写入/重开、九模块校验、普通权限重开、恢复和工作进程中断后的观察恢复。专用沙箱已关闭。

修复组件的独立测试副本通过完整哈希与真实客户端只读预检：Kumiryo 0.2.4、9 模块、95 规则、无阻止项。用户随后明确确认“一键配置成功完成，重新打开正常”，按**用户实机验收通过**记录。该次成功操作的新机器日志未由维护者重新读取，不把用户确认当作内核逐字段自动核验。私人电脑名、操作编号、PID、日志和备份不公开。

## 开源工程验证

稳定版 .NET SDK 10.0.403 完成六个工程编译，0 警告、0 错误；同一 SDK 下 136 项功能检查通过。所有工程生成依赖锁文件。公开前的历史凭据扫描通过；当前源码、工作流、依赖漏洞和云端 CI 的最终结果见 GitHub Checks 及 [开源维护记录](reports/开源发布-20261104.md)。

稳定 SDK 的干净源码本地分发再次通过 732 个清单文件/733 个便携文件检查，并在断网、无 dotnet/Codex 的 Windows Sandbox 26100 上完成实际采集和 WinUI 截图。新增包管理清单、SBOM 和 9 个公开附件的白名单/哈希检查通过；三种清单均通过官方 Schema 校验。

标签工作流会从同一提交重新构建安装器和便携包，并在当前源码的 CI required 成功后才生成公开 Release。SBOM、WinGet/Scoop、SHA-256、来源和 SBOM 证明与对应版本一起发布。本机分发验收不冒充云端最终产物的运行验收。

## 仍有的边界

- 内核逐字段读回仍受第三方客户端接口限制，文件一致不能证明所有系统副作用已生效。
- 热点、网卡、驱动、上游网络和其他 Windows 构建需要相应实测。
- 普通 CI 不执行真实 UAC、修改贡献者启动项或重置其网络；管理员及安装恢复测试使用专用 Sandbox。
- 自动安全扫描覆盖已知模式和公开漏洞源，不是无漏洞保证。
