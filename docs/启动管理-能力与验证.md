# 启动与后台监测：能力及验证记录

版本：1.2.0，Windows 11 x64，扫描监测与单项控制。日期：2026-10-29。

## 权限与采集范围

| 来源 | 普通 UI | 单次管理员 / LocalSystem | 边界 |
| --- | --- | --- | --- |
| Run、RunOnce、StartupApproved、启动文件夹 | 当前用户及可读机器范围 | 扩大其他账户和受限项 | 32/64 位分开；未知状态不猜测；设置和任务管理器可能操作同一状态 |
| 未加载用户 hive | 能复制时只读解析 | 访问范围扩大 | 私有临时副本、128 MiB 上限、只解析常见启动键；不回放事务日志 |
| 打包应用启动 | 当前账户及可用 API | 目标用户 API 允许的范围 | 记录 manifest 与实际状态；缺失 executable/COM 注册不猜路径 |
| 服务、驱动 | 原生 SCM 枚举、可读注册表 | 扩大受限字段 | 区分真实服务、驱动、模板、用户实例及仅注册表登记；触发/手动不等于禁用 |
| 计划任务 | 可见任务、XML、触发与动作 | 包括可读取的隐藏/其他账户任务 | COM 动作尽量关联登记；保留 XML，不执行动作；受限任务明确列缺口 |
| 系统间接入口 | 可读注册表 | 扩大范围 | 包含 Winlogon、Session Manager、LSA、AppInit、IFEO、SilentProcessExit、Active Setup 与脚本等所列位置 |
| Shell、打印、网络 | 所列批准扩展和提供程序 | 可读的扩展范围 | 不把全部 COM/Winsock 登记都当作开机启动；软件私有后台机制不保证穷尽 |
| WMI 永久订阅 | root/subscription 可访问项 | 权限允许项 | Filter、Consumer、Binding 分开保存，应联合判断 |
| 进程快照 | ToolHelp、可读路径/命令、创建时间 | 增加可读字段 | PID 会复用；父 PID 只表示关系，来源不确定时明确标记 |
| ETW 进程/任务 | 显示权限降级 | 机器组件实时进程创建/退出和任务事件 | 仅自己创建的会话；开启前/事件丢失期间不保证完整；不干扰其他 ETW 会话 |
| 文件与建议 | 本地路径、版本和离线嵌入签名 | 同样的保守逻辑 | 不联网查信誉；目录签名未核实不等于未签名/恶意；缓存按文件长度和修改时间，非内容哈希审计 |

注册表/目录/任务变化提供重新核对线索，普通状态采样为 5 秒，完整补扫为 5 分钟。对宽范围注册表通知先核对控制字段采样，避免无关运行状态写入造成连续全扫。短暂变化和软件私有机制仍可能落在缺口内；没有追溯全部历史启动的保证。

本机第一轮普通权限样本本次实际读取 1,196 个入口（18 登录/文件夹、12 打包应用、856 服务/驱动及登记、213 任务、20 间接入口、75 扩展、2 WMI），并保留 26 个本轮未重新确认的旧入口。数量随机器状态变化，不能当成固定设备清单或开机常驻数量。

## 提醒和分析

关注值仅在确认当前控制状态后保存。先写 SQLite 告警，再提交 Windows 通知。缺口、一次性入口消失或未知状态不会直接推定删除/覆盖。重复偏离合并计数，恢复结案，再偏离产生新事件。通知中心清空不会删除应用历史。未确认修改来源时，不把荣耀管家、微软管家或其他进程写成确定原因。

自动规则带版本，建议允许人工复核。用户用途与事实分开保存，用途变化使旧分析指纹失效。MCP 只读取待分析区/批次内证据，回传只更新建议；本机 ID、批次、配置/文件标识/用途指纹和严格字段校验共同约束结果。默认脱敏常见令牌参数，但不能保证所有私人内容均自动识别。

## 实现中的保护和生命周期

- UI、通知与模型建议以普通权限运行。管理员代理仅接受固定扫描/组件与有类型的单项操作，不接收任意命令、SQL、输出路径或脚本。
- 管道校验实际连接进程/账户，机器服务也须匹配 SCM 注册 PID 和受控路径。机器策略只授权一个 owner；其他账户不能直接读取机器数据。
- LocalSystem 程序复制到受控 Program Files，不从用户可写便携目录运行。安装验证目录 owner、重解析点、文件内容复制和版本目录；机器数据限管理员/System。
- 升级保存数据库备份，准备新版本后切换服务，失败尝试回到旧服务路径。未知数据版本在执行建表前拒绝。未做跨大版本迁移承诺。
- 默认不以 SYSTEM 访问 UNC、网络映射盘或重解析路径；相关目标列为未核实。hive 副本限当前采集账户/管理员/System，复制有大小上限并清理。
- SQLite 事务、WAL 和写入锁保护建议校验/提交；普通事件容量阈值不清除告警。物理文件增长和磁盘写满仍需实际观察。
- 关闭 UI 可进入托盘，退出托盘不停止机器组件。暂停和手动扫描分开。服务接收开机后的会话/电源恢复线索进行补扫，但不推定每次恢复都是完整重启。
- 系统通知注册有失败说明和历史记录。通知点击的早期激活先缓存事件 ID，再显示对应历史页；仍待真实点击链路验收。

1. 本机完整管理员全局扫描及一次真实重启的开机轨迹。前段测试时 UU 服务停止，无法确认 UAC，因此管理员测试放在沙盒进行。收尾复查时 UU 服务已经恢复 Running，本次没有新增宿主机授权请求。
2. 原生 Acrylic/Mica/MicaAlt 的人眼视觉效果、真实通知点击/应用关闭后唤回、多显示器/DPI/高对比度全排列。
3. 其他 Windows 11 构建、ARM64、受保护反恶意软件、其他厂商私有配置和其他电脑的热点可用性。
4. 长时间压力、磁盘满、突然掉电和每个升级失败阶段的故障注入。已有事务/备份/回退不等于这些场景都经过验证。

单项修改遵守 Windows 权限和保护，不提供批量停用、删除、争抢管家保护、关闭安全机制或静默提升 UI 权限。控件清单与恢复边界见 README；管理员原始备份不信任本地历史副本。

## 热点问题的当前证据

用户反馈安卓平板提示不可上网，但部分网页可访问，荣耀智慧中心部分功能失败。
只读设备枚举曾同时看到平板和手机分配到不同 IPv4，热点来源为 Kumiryo，WLAN 转发仍保持已验证状态；随后复查平板已不在连接清单。
这些证据只能排除“整条热点完全断开”和本次观测下的来源选错，不能确认是联网探测误判，也不能证明某个荣耀域名、DNS、IPv6 或代理规则就是根因。
仍需平板端私人 DNS 状态、手机关闭移动数据后的对照，以及具体失败功能/时间。没有为此重置热点、DNS、代理、防火墙或远控服务。
