# 安全架构与审查

本文件描述威胁边界和检查范围，不是“没有漏洞”的保证。漏洞通过 [安全策略](../SECURITY.md) 的私密入口报告。

| 攻击面 | 现有约束 | 主要验证 |
| --- | --- | --- |
| 管理员 UI 代理 | 原账户、管道服务端身份、随机管道名、类型化请求 | 协议/身份与拒绝非法请求检查 |
| LocalSystem 机器采集 | 受控程序和目录、SCM PID/owner 核对、管道 ACL 和连接用户；不提供通用任意命令执行 | 服务边界 Sandbox 检查 |
| 启动修改 | 支持来源/操作白名单、重新扫描定位、当前指纹、备份、回读和保护服务检查 | 控制策略、恢复冲突和隔离控制检查 |
| 配置迁移 | 九模块模板、凭据拒绝、当前用户 DPAPI、目标身份、路径/链接和保存稳定性核验 | 模块、授权、写入、回滚与中断恢复检查 |
| 进程退出 | 路径/SID/会话/创建时刻/句柄复核，仅本次授权 UI；不结束进程树 | 未授权保留原进程、精确退出和普通权限重开 |
| 文件与数据库 | 私有 ACL、实际路径、无重解析点、原子替换、独占维护和原件备份 | 文件、坏库、热回滚和恢复检查 |
| AI 与导入 | 名称/描述/命令为不可信数据，严格字段/本机/批次/指纹校验，桥接无控制命令接口 | 解析、过期结果、混合批次和队列检查 |
| 网络与日志 | 热点隔离、有限读取/修复边界；诊断默认本地保存并过滤常见凭据 | 故障恢复与日志脱敏；提交前仍需人工检查 |

## 开源和供应链

- 源码、历史用 Gitleaks 扫描，二进制工具下载和本地缓存均验证 SHA-256；不通过大范围忽略隐藏潜在泄漏。
- 当前版本锁定稳定 SDK 和 NuGet 传递依赖；全量漏洞查询失败时停止检查，不将无法联网当作“未发现漏洞”。
- CodeQL 对实际 C# 编译执行 security-extended 分析；依赖 PR 再做 dependency review。PowerShell/YAML 由语法、actionlint 和固定 SHA 策略检查，不能将 CodeQL 当作覆盖这些语言。
- 普通 PR 不获得发布环境或密钥，不使用 pull_request_target 执行外部分支代码。发布仅接受 main 中的版本标签，上传路径限定为已验证 packages。
- 安装器编译器和 VC++ CRT 保留官方签名验证；当前应用自身无 Authenticode 证书，不宣称已签名。
- 私密漏洞报告、Dependabot、推送保护、分支/标签规则及发布不可变配置以 GitHub 实际状态为准，记录在 [开源维护记录](reports/开源发布-20261104.md)。不把配置文件存在当作平台功能已启用。

## 披露和修复

维护者先复核影响、最低权限和受影响版本，再协调补丁、回归、发布和公告。原始凭据、用户数据和利用细节不公开。发现泄漏应先撤销/轮换凭据；删除当前文件不能清除历史或撤销已泄漏的凭据。

实际用户工作环境不用于破坏性测试。UAC、真实关机、驱动/热点行为和第三方客户端副作用需要相应环境验证；CI 静态分析和功能测试无法完全替代。
