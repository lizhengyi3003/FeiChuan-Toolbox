# 稳定性修复与验收 · 2026-11-02

最终版本：1.5.2。本地界面与后台采集组件均已更新，依据 `installed-update-152.json` 和普通权限重开回执。731 项安装文件核验通过，受保护的远控、代理及 Process Governor 核心服务保持运行。

## 本轮处理

1. 热点 Windows API 从 WinUI 进程移到受控 Engine 子进程，核对父 PID、启动时刻、会话和 SID。进程异常、超时及协议错误留档；不重放未确认的启停操作。
2. 全局设置增加独立的当前账户登录自启开关。预览后只修改自己的 Run/StartupApproved 值，备份、回读及失败恢复均保留；机器服务独立控制。
3. 托盘启用 `NIF_SHOWTIP`，保留 WinUI 3 MenuFlyout 菜单和原生通知区接口。系统版本 4 图标协议的悬停标志见 [Microsoft 文档](https://learn.microsoft.com/windows/win32/api/shellapi/ns-shellapi-notifyicondataw)。
4. Microsoft Store 增加只读端点检查、失效本地代理受限修复及 Windows 缓存修复。实际运行了 `wsreset`，用户随后确认关闭代理时商店内容可以正常加载。未通过改写整组 Kumiryo 规则来处理，不能据此确定原始故障一定由缓存造成。系统缓存修复依据 [Microsoft Support](https://support.microsoft.com/en-us/accounts-billing/microsoft-store-doesn-t-open)。
5. 数据统一至 `%USERPROFILE%\.FeiChuanToolbox`。此前确认了桌面启动与打包宿主启动的 AppData 实际位置不同；健康库在线迁移，合入另一个损坏旧库中可核验的历史，保留全部原件和恢复前备份。现有 382 项建议及 436 条建议历史保留。
6. 热点开启后先做五秒稳定观察，持续保留共享管理对象。实测手动开启后连续观察约一分钟，连接一台设备，自动重连关闭，未再次自关；19:59 的手动 TUN 断开/恢复期间工具箱进程保持运行并记录提示。该测试确认网络断开场景，未把仍在运行的 Kumiryo GUI 误称为完整退出进程。
7. 设置内日志查看器支持类别、严重等级、时间和关键词，支持详情、复制、脱敏导出、刷新用户及授权机器日志。机器数据仍通过核对 SCM PID 和 SID 的 IPC 读取，不放开 ProgramData 私有目录权限。

## 关机事务恢复补修

固定持有未提交事务并强制结束进程，复现了 SQLite 776（READONLY_ROLLBACK）：只读连接不能完成遗留热回滚日志的事务恢复。依据 [SQLite 错误码说明](https://sqlite.org/rescode.html#readonly_rollback)，1.5.1 对该错误单独处理：排他维护，成套归档数据库及旁日志，让 SQLite 自身回滚未提交事务，再重新检查完整性及版本。真实损坏不自动变空库，未知或未来结构不进入应用写入。

128 项核心检查包含三轮确定产生热日志的强制结束、两进程并发恢复、保留原件、恢复核验备份、独立设置、登录自启的隔离注册表操作、日志分类/凭据过滤和热点子进程崩溃隔离。WinUI 自动化覆盖坏库下全局设置、登录开关、分类/等级交集、空结果、搜索、页面重试、启动诊断和托盘回调。一次桌面截屏捕获到了其他应用，已判为无效，正式界面验收改用实际 XAML 树截图。

两次不兼容的临时 Python 管道探测被机器服务拒绝并留档；随后使用带标准 Windows 模拟级别的客户端验证，授权诊断读取成功。该拒绝记录不代表实际 WinUI 客户端无法连接。

本轮没有重启整台电脑，不能把进程强制结束测试称为已完成真实关机/断电验收。Kumiryo 完整 GUI 退出与断开 TUN 是不同测试；本轮保留这一证据边界。
