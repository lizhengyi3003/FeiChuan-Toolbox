# 本地安装版启动失败排查与保护

2026-11-01 实机排查对象：`D:\Program Files\TunHotspot\TunHotspot.exe`。

## 发现

Windows 应用程序事件记录了当晚多次启动崩溃，最后报告的模块为 CoreMessagingXP.dll / combase.dll，异常为 `0xc000027b` / `0x80004005`。22:22 的转储包含 `SQLite Error 11: database disk image is malformed` 和 `ToolboxStore.get_Latest / Get / Query` 调用信息。此前 16:35 的操作日志也记录过读库损坏异常。

本次 22:39 普通权限启动安装版成功。只读 `quick_check`、各表读取，以及 SQLite 在线一致性备份后的 `integrity_check` 均通过。由此可确认此前有启动读库失败，但本次没有复现同样错误；原始损坏原因和再次出现的条件仍待核查。没有证据将原因归到荣耀电脑管家、EFS、系统运行库缺失或上次禁用的启动任务。

## 实现

- 普通界面在写入设置、创建热点页及启动定时器前，以独立只读连接检查已有数据库的完整性。
- 启动失败显示独立 WinUI 3 诊断窗口，包含错误摘要、重试打开、诊断目录和关闭按钮，取代重新抛出异常造成的静默闪退。
- 重试只清理当前进程的 SQLite 空闲连接并重新加载；没有自动删除、覆盖或重建数据库的功能。
- `ToolboxStore(string root)` 原有构造接口保留，新增带完整性检查参数的重载，避免改变其他组件的二进制调用接口。
- 启动日志增加进程号和权限信息；完整异常记录在本机操作日志中。

## 验证和证据

- `tools/test/ui/Test-StartupFailureUi.ps1` 注入一次隔离 QA 启动异常，经 UI Automation 确认错误提示、实际点击重试，随后进入独立临时数据目录的工具箱并正常退出。

## 安装范围

本次只更新已核对的七个安装文件，更新脚本校验新旧哈希，更新前备份程序文件，失败时回退。实际部署是否成功，以 `update-result.json` 和独立安装文件校验结果为准。系统启动配置、数据库文件、UU 远程、Kumiryo 及机器采集服务不属于修改对象。

实际更新已经完成。安装目录 731 个清单文件通过独立复核，普通权限安装版重新启动，UI Automation 确认实际工作区、全局扫描按钮和总览已加载，窗口正常响应；后台采集、UU 远程及 Kumiryo 服务进程均保留。自动重新打开的辅助脚本曾因旧版 PowerShell 无法解析 `Get-FileHash` 而失败，已改用 .NET SHA256 并实际重新执行成功。数据完整性复查通过，没有替换现有数据库。
