# 安装前 UAC 提权修复 · 1.5.5

用户在 1.5.4 的目录页确认管理员权限后，没有出现 Windows UAC。真实日志显示目录预检返回 10（错误 5、无写权限），之后 ShellExec 失败，却统一显示“未获得管理员授权”。

## 原因与改动

Inno Setup 的 ShellExec 明确不支持在安装开始前运行安装器自身，见 [官方说明](https://jrsoftware.org/ishelp/topic_isxfunc_shellexec.htm)。只读最小复现使用同样调用，在普通令牌下得到 False/错误码 5，无 UAC。原先的错误提示混淆了调用失败和用户取消。

提权改用 [Windows ShellExecuteW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecutew)，verb 为 runas，父窗口为安装向导，保留目标目录、任务、原始 SID 和一次重试标记。Windows 正常执行 UAC；不会绕过授权。成功启动后退出旧向导，新进程仍通过既有协调器核对账户。原先 lowest 的当前用户安装语义保持；提升令牌不切换为其他账户的安装登记。

移除 UAC 前多余的确认框。启动失败记录返回值及 Win32 错误；取消授权可重试；错误窗口给出错误码、系统描述及日志位置。目录页不再把同一失败叠加显示两次。

`installer/Elevation.iss` 是正式代码唯一入口；`tools/test/local/UacHandoffProbe.iss` 引用该文件验证同一调用路径。检查程序不包含复制文件、卸载登记或服务操作，父子进程均在安装开始前退出。普通目录预检、自动退出本软件、备份、731 文件核验、失败恢复与冲突保护沿用既有协调器。

## 验证范围

当前结果见 [当前验收](../VALIDATION.md) 和本轮 completion.json。宿主交互式检查只验证提权及账户，不自动执行宿主程序替换。历史升级回归见 [1.5.4 验收](安装回归验收-1.5.4.md)，不能把它当成交互式 UAC 已验证。

实际 1.5.5 安装包的目录页已在宿主触发 Windows UAC：普通父进程调用原生接口返回 42、错误码 0；新的管理员进程通过原 SID 身份检查，原目录 `D:\Program Files\TunHotspot` 及 HKCU 安装登记语义保留。证据是 host-uac-proof.json 和两份安装日志；代理停在实际安装前，后续安装由用户继续。
