# 1.5.3 安装升级故障仿真 · 2026-11-03

范围：只读核查本机安装；实际安装、ACL 故障注入及 MCP 停启均在断网 Windows Sandbox 内执行，没有用仿真安装覆盖本机目录。

## 复现结果

| 场景 | 结果 | 结论 |
| --- | --- | --- |
| 安装 1.5.2 后运行安装目录中的 Engine --mcp，再升级 1.5.3 | 失败，安装日志明确出现 Engine/clrjit.dll、DeleteFile 失败、错误代码 5、拒绝访问 | 界面退出不代表 Engine DLL 已释放；MCP 可单独占用运行库 |
| 上述失败并显示回退后，对照升级前文件 | 文件并未全部保持原样 | 不能把安装器“撤回更改”当成已恢复完整旧版本 |
| 重置到 1.5.2，给隔离安装目录注入无写入/删除权限，再升级 | 失败，文件保持原样 | 目标写入权限是另一项必须提前核查的条件 |
| 解除 MCP 占用、恢复目录权限后，用同一个 1.5.3 安装包升级 | 成功；731 文件与安装清单一致，UI/Engine 均为 1.5.3 | 未发现包损坏；失败依赖实际升级时的目标状态 |

过程退出码与日志里的 Win32 错误码分别记录；结论中的错误 5 来自日志的 DeleteFile/拒绝访问，不只依赖安装器进程退出码。

第一轮权限夹具仅拒绝单个文件，父目录的删除子项权限仍可使安装器替换该文件，因此这个场景不足以模拟只读安装目录。其记录原样保留；第二轮改为拒绝隔离目录及其子项写入/删除，并重新建立每个场景基线，才得到上表的独立权限结果。

## 本机只读发现

- D:/Program Files/TunHotspot 的普通权限目录访问探测返回 Win32 5；探测只申请已有目录的 FILE_ADD_FILE 句柄，没有创建文件或写入字节。
- PID 38860、5908 的 Engine --mcp 正在加载实际安装目录内的 clrjit.dll、TunHotspot.Core.dll 等模块。机器采集组件使用另一个受控版本目录，不能将这几个进程混为一谈。
- 用户这次安装失败后，主程序已为 1.5.3，但安装清单有 5 项不匹配：Engine/TunHotspot.Core.dll、Engine/TunHotspot.Engine.deps.json、Engine/TunHotspot.Engine.dll、Engine/TunHotspot.Engine.exe、Notices/dependencies.json。卸载登记仍为 1.5.2。

因此本机是部分更新状态，尚未完成一致性修复；本轮没有擅自写入原安装目录或终止本机桥接/远控/代理进程。也没有取得用户当时的原始安装日志，不能断言当时报错的具体文件名一定就是沙盒中首先遇到的 clrjit.dll。

## 安装器缺口与修复方向

现有 AppMutex 只检查主界面；CloseApplications=no 未处理独立引擎占用，PrepareToInstall 中也没有针对目标文件/权限的预检。PrivilegesRequired=lowest 默认不申请 UAC，对当前这个受保护目录还存在权限条件。

下一步应在任何文件替换前核实 UI 与 Engine 占用、目录和现有文件权限，明确显示具体进程/文件；受保护路径提供明确的提权或用户目录安装方案。升级前保留完整程序备份，异常后核验并恢复一致版本，不能只依赖默认撤回提示。处理目标限定为本软件，保留用户数据和其他服务。

本机修复需要先释放本软件的 Codex MCP 文件占用，再在有目标写入权限的上下文中执行完整覆盖及 731 文件回读。仅关闭托盘或仅右键管理员运行，都不能单独解决上述全部条件。
